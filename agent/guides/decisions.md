# 先判断当前需求

这份材料帮助理解当前问题，不提供风格选项、网站类型菜单或固定页面步骤。根据已有信息作判断，不要求用户先填一套设计问卷，也不要求每次把思考过程写成同样格式。

## 找到本次真正要解决的事

- 谁会使用页面，带着什么问题进来？区分已知事实与自己的假设，不用虚构的人群画像替代用户要求。
- 用户需要阅读、查找、比较、编辑、决定，还是持续操作？这些任务可以同时存在，主次来自实际需求。
- 完成任务之前需要知道什么，之后需要看到什么结果？页面数量、导航和内容顺序由这些关系决定。
- 有哪些真实内容、数据、图片与品牌材料？已有内容先使用；缺少事实时说明缺口，不补造评价、统计或业务承诺。
- 目标设备、使用环境与已有工程有什么约束？不因为熟悉某种实现就擅自改变用户的技术要求。

没有影响结果的关键缺口时，说明合理假设并继续。只有现有材料无法确认、且会改变主要任务或造成不可逆后果的关键缺口，才需要询问；已有明确授权的工作继续推进，不重复索要确认。不要因缺少一张装饰图片就停下全部工作。

## 从内容决定结构与表现

内容之间是并列、先后、归属、因果，还是需要比较？先确定这些关系，再决定是否需要容器、表格、分栏或导航。只有一小段内容时，可以直接组织这段内容，不为凑页面增加区块。

视觉表现服从本次内容、品牌、受众与情境。颜色、字体、材质、图形、密度、对齐和动效都可以重新选择；本库的预览不能替代品牌规范。没有风格要求也不等于自动选用本库展示站的外观。

## 避免把判断变成另一套模板

- 不从一个整页例子开始换字，再寻找理由保留它的所有区块。
- 不从有限骨架或风格名单里强选一个，不要求每页出现某种视觉记忆点。
- 不随机打乱布局、强制换颜色或要求与上一页不同，以此假装做了设计。
- 内容和任务相同、属于同一产品时，保持一致可能更合适；相似本身不是错误。

结果应能对应当前任务。需要解释时，说明影响结果的设计选择与依据即可，不强制理由数量、文档格式或固定话术。
